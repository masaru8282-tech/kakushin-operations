# KAKUSHIN 受付業務システム

仕様書（抽出仕様 v1.0、2026/10/22）に基づく、独立した固定計算エンジンとローカル操作画面です。Python 3.11以上、追加依存なしで動作します。**現在はシャドーモードです。本番Sheets更新・Slack通知・業者送信・月替わりは実行しません。**

## クラウドで画面を開く（Windowsへのインストール不要）

GitHubの **Code → Codespaces → Create codespace on main** から起動できます。画面が自動で開かない場合は **PORTS → 8000 → Open in Browser** を押してください。架空データ専用・一時DBのデモであり、本番には接続しません。詳しくは [画面を開く手順](docs/TEST-ENVIRONMENT.md) を参照してください。

## 起動

```bash
cd /workspace/kakushin-operations
python3 -m unittest discover -s tests -v
python3 -m kakushin serve --port 8000
```

上の通常サーバーはローカルの8000番ポートで起動します。インターネットへ直接公開しないでください。ローカルの操作者を信頼する単一マシン構成で、複数利用者の認証・ロール管理はまだありません。このCodexセッションではブラウザー用転送URLの発行機能がありません。クラウドでの表示には上記Codespacesを使い、Codex内部ではCLI・HTTP・実ブラウザーで検証します。

```bash
python3 -m kakushin run examples/reservations.csv \
  --month 2026-10 --business-date 2026-10-22 --completeness full
python3 -m kakushin tool examples/warehouse-order.json
python3 -m kakushin tool examples/draft-plan.json
```

CLIの集計は結果JSONを標準出力へ返します。PLに保留があれば終了コード2、成功は0です。サンプルはすべて架空の検証用データです。実データをGitへ追加しないでください。

## 使える機能

- 速報13/14/15列・詳細44列CSVの判別、UTF-8/BOM、正規CSVパース、日付差・JPY整数円・ID重複・IDなし重複候補の検査。
- 全35列×6項目のPL候補。CO月で全額計上、実額OTA手数料、人数×泊数×200円、八代税空欄。2件の取消料特例はID・施設・金額・元日付・適用月で限定。
- 39室のリネン行マスター、固定使用数、次回予約の人数×最大3泊のタオル。次回未確認ではタオルのみnull。
- 現場の数列報告の品目対応、月初基準値の差分補正、準備済み数からの追加必要数。
- 入室可否、3日間の熊本搬入候補、次回納品までの部屋在庫予測。使用と搬入の数量を分離し、全品目の目標補充を計算。
- P08のタオル減量は未承認の提案として別表示。3日合計の約10%を四捨五入し、次回納品までの余裕の大きい部屋へ配分する案。ルール正本とは扱いません。
- 熊本の合法発注候補列挙、発注単位・上限・残置上限、発注済み固定。時点別イベントで日中の不足を検出。
- 八代の自室→入室確認済み他室→最小業者必要数の候補。熊本と別計算。移動は業者入庫・清掃使用に混ぜません。
- 原本CSVのSHA-256保存、SQLiteの実行・監査台帳、同一入力再実行の重複排除、DBバックアップ。
- PLスナップショットの見出し・月別合計式・入力セル所有権・数式/保護を検査する差分ライブラリ。
- Slack履歴とSheetsの**読取専用**クライアント、Slack署名検証・イベント重複排除の基礎部品。現時点で本番との結線はしていません。

## 計画の入力と限界

画面のCSV処理はPLと清掃使用候補までを保存します。在庫や搬入実績をCSVから推測しません。在庫・発注画面の計算は入力したJSONに対する独立した計算です。`draft_plan` はCLIの `examples/draft-plan.json` の形式で実行できます。

`room_stock` は業務日朝の未使用予備在庫、`usage_events` は対象日ごとの**既存準備・実績と照合済みの**必要使用数です。CSVから作った使用候補を無条件に二重投入しないでください。`reservations` はその部屋の在室確認に必要な全範囲を宣言します。`reservation_scope_confirmed=false` では搬入機会を確定しません。`permissions` は `施設:部屋@YYYY-MM-DD` の部屋日別許可です。

`forecast_until` は次回月水金納品日まで、かつ3日分を含めます。2026/10/31を超える予測は承認されていないため拒否します。月末に3日分を収められない場合も保留します。倉庫を入力する場合は、既存確定入出庫の `events` と候補搬出の `dispatch_sequence` を明示し、予定と実績の二重投入を避けてください。未知在庫は0として扱いません。

搬入候補は不足する部屋に対し、入室優先度→早い日の順で1回の目標補充を提案します。施設まとめ、倉庫制約に応じた再配分、目標超えの大量補充、複数回補充の最適化は未実装です。解消しなかった不足は結果に残ります。すべて `CANDIDATE_NOT_CONFIRMED` であり、確定済み計画ではありません。

## 保存・バックアップ

`.runtime/` に `operations.sqlite3` と `sources/<SHA256>.csv` を保管します。Git対象外、ディレクトリ0700・ファイル0600です。原本CSVには個人情報が含まれ得るため、アクセス制限・暗号化ディスク・保存期間を本番導入時に確定してください。DB結果は個人連絡先・ゲスト名を保存しません。

```bash
python3 -m kakushin backup /tmp/kakushin-backup.sqlite3
```

このコマンドはDBのみです。復旧時はDBと原本アーカイブ `sources/` の両方を保全してください。バックアップ先は既存ファイルを指定できません。復旧テストはSQLiteの読戻し・整合性チェックまで自動検証しています。本番復旧演習・定期バックアップ・保持期間は未設定です。

## 本番へ進む前に

[懸念・未実装事項](docs/CONCERNS.md) と [受入チェック対応](docs/ACCEPTANCE.md) を確認してください。資格情報はチャットやGitへ貼らず、実行環境の秘密管理で設定します。本実装は資格情報を要求せず、外部への変更・送信を行いません。元の仕様書は個人情報を含むためローカルの `docs/specification.md` にのみ保持し、Gitには含めません。共有する列名辞書は [docs/csv-schema.md](docs/csv-schema.md) です。


実予約に紐づく取消料特例は `.runtime/private-exceptions.json` に分離しています（Git対象外）。新しいPCへcloneした場合は特例がなく、対象行は保留になります。必要な場合のみ承認済みの設定を安全な経路で配置してください。別の保存先は `KAKUSHIN_EXCEPTIONS_FILE` で指定できます。設定には予約IDごとに `room / ota / sales / fee / ci / co / column / month`、任意で `guests` を持たせます。実予約の設定をIssue・チャット・Gitへ貼らないでください。

初めて画面を表示する方は [PCでのテスト手順](docs/TEST-ENVIRONMENT.md) を参照してください。

クラウド向けデモを手動起動する場合は `python3 -m kakushin serve --demo --host 0.0.0.0 --port 8000` を使用します。プロキシのHostと埋め込みを許可するのは、この架空データ専用モードだけです。通常モードの外部バインドは拒否します。
