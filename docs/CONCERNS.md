# 懸念材料・本番運用までの残作業

仕様書を実装上の根拠として使用し、文書中の過去の処理・提案を現在の外部実行許可とは解釈していません。

## 本番運用を阻むもの

| 事項 | 影響と現在の動作 | 必要な対応 |
|---|---|---|
| 実CSV・更新前スナップショット未提供 | 仕様の数値例と架空データでは検証済み。実績との完全一致は未検証 | 原本CSVと更新前の値・数式・見出し、最新実数・時点を使ったシャドー照合 |
| Slack App / Google認証・共有未設定（P05/P06） | 読取クライアントのみ。Webhook受付、CSV自動取得、実Sheets反映、通知は未接続 | 独立App・必要スコープ・対象共有・秘密管理・接続テスト |
| 担当者・管理者・権限・同時編集運用未定（P02/D02） | 通常UIはローカル操作者用。クラウドのデモは架空データと一時DBに限定。セル所有権が不明なら投影拒否 | 本番認証、担当者のIDと権限、対象日のロック・編集停止/競合解決方法 |
| Sheetsには原子的なcompare-and-swapがない | 直前照合と書込間にも他者編集が可能。読取前提の差分のみ提供 | 実務上の排他運用を決定したうえで限定更新・ジャーナル・再読込・タイムアウト復旧を実装 |
| 月替わり手順未確定（P01） | 自動クリア・タブ作成・11月リネン予測は無効 | 旧月保全、初期値・実績/予定繰越の正式承認と復旧試験 |
| 本番への限定書込・通知・キュー実行は未実装 | ローカルの候補生成だけでは本番移行完了ではない | 認証・所有権・運用確定後にアダプタを実装し検証環境で受入 |

## 数量・計画の未確定ルール

- P08：搬入日、施設まとめ、タオル減量の丸め・母数・配分順位は未承認。`planning.POLICY` は比較可能な開発提案で、正式ルール公開はしていない。
- P10：CO→納品→搬出→入庫→使用→CIは実時刻が必要。日付だけの案は条件付き。時点別入力があれば午前不足を検出するが、時刻は推測しない。
- P03：八代の移動台帳は既存Sheetsに未整備。内部候補は分離するが、使用や入庫へ偽装投影しない。八代業者の曜日・単位・上限と正式目標は未確定。
- P07：桜町804 S/Dの既知数式不整合は未修正。独立計算を採用し、本番スナップショットとの照合が必要。
- 出水：通常使用・目標・CSV対応・基準在庫が未確定。通常計算は保留。撮影用の過去指示を一般化しない。
- PL：AF510、AH自適荘、番号付き二本木、未知OTA、返金/負数/外貨は保留。既知取消料2件を一般化しない。IDなしの特例適用は自動化していない。
- 自由文Slack報告全体の施設・時点・訂正関係の抽出は未実装。現在は明示された部屋の数列を検査する。数列だけから施設・日付を補完しない。
- 清掃使用は候補。初回CI準備や既に準備済みの記録を自動復元しない。追加必要数は `additional_preparation` へ実数を渡して計算できる。
- 原本SHAでの再実行は同一化する。行順・改行が異なる別ファイルは別runだが、計算は加算せず再集計する。独立したイベントの実績化・訂正の永続業務台帳は未実装。

## 運用・セキュリティ

- 通常構成は単一マシン用SQLiteとloopback専用HTTP。`--demo` の場合のみ外部バインド・転送Host・埋め込みを許可し、実CSV受付を拒否する。HTTPS公開・複数ユーザー・常駐キュー・役割認可・監視は導入前に別途実装する。画面からの操作にCSRF検証、Host制限、CSPを適用。
- ローカルアーカイブに個人情報を含む原本CSVを保存する。保存期間・暗号化・削除・アクセス監査の本番方針を確定する。
- 本番向け自動送信は無効。業者文は未発注案と発注済みを分け、LINE/業者へ送る場合は人間が内容を確認する。
- デプロイ・環境Publishは未実施。GitHubの保存状態はリポジトリのコミット履歴を参照。元仕様書と実予約特例はローカル限定でGit対象外。

読み取り専用ファイル照合モードを追加。Codespaces Privateポートの認証と正確なHost制限を前提とし、実ファイル・確認条件・結果のサーバー保存はしない。使用数一致とは別に、実数・在室・実績と在庫式の確認は引き続き必要。

3日間画面は既存Excel記載を保持した予測と発注候補を提供。追加補充・タオル減量案を既存搬入や業者発注へ自動採用する機能は未実装。既存セルの所有権／予定実績／発注状態と実時刻は引き続き確認対象であり、未確認事項を在庫0や架空の入庫で消さない。
