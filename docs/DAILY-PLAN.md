# 次の作業：リネンの3日間計画と指示文

この画面は、予約CSVとリネンExcelから搬入の記載・在庫予測・業者数量を確認します。JSONの入力、PL Excel、例外条件ファイルは不要です。本番シートの変更、業者・LINE・Slackへの送信は行いません。原本・結果をサーバーへ保存しません。

## 既存Codespacesを更新する

開発画面のターミナルで次を実行し、管理画面を再読み込みします。

```bash
git pull --ff-only && python3 .devcontainer/start_demo.py --restart
```

Privateポートの設定はそのままにします。Windowsへのインストールは不要です。

## 使い方

1. **3日間計画** タブを押します。
2. 予約CSVとリネン管理Excelを選択し、開始日を指定します。すでに **ファイル照合** を実行した場合は、照合結果の **次へ：3日間計画を確認** から、ファイルを選び直さずに進めます。
3. **3日間の予定と発注案を表示** を押します。日別の搬入記載が表示されます。搬入記載なしの日も表示します。
4. **熊本業者の発注数量** で納品日ごとの状態を選び、**発注状態を反映して再計算** を押します。
   - **未確認**：Excel記載数量を保持。候補は比較表示しますが業者本文のコピーは無効です。
   - **未発注**：月水金の納品に対する発注単位・上限・搬出後上限・次回納品までの搬出を検査し、合法な候補を計算します。
   - **発注済み**：記載数量を固定して検査します。解なし・上限不整合・未記載の品目があれば、数量を勝手に変更せずコピーを保留します。
5. **LINE用：熊本の搬入予定** または **LINE用：八代の直接搬入予定** の **本文をコピー** を押します。未確認の状態や順序条件を含むので、内容・現場状況を確認してから利用します。画面からは送信しません。
6. **不足・未確認事項** を開くと、表上の不足、納品前に搬出した場合のリスク、次回予約不明などを確認できます。**熊本倉庫・10品目の予測** で朝在庫・記載納品・搬出・日末予測を見られます。

## 追加補充案とタオル減量提案

追加補充を計算するのは、対象期間の予約・在室範囲を操作者が別途確認した場合だけです。月末CO基準のCSVに滞在中予約が全て含まれるとは限らないため、このチェックは初期状態で無効です。

追加案は既存入庫を差し引いて目標補充を計算し、既存予定の上書きや二重計上をしません。入室禁止日、朝在庫のマイナス・未確認、使用数量不明等は補充で帳尻を合わせず保留します。初期の決定規則は優先度→早い日の順、1回の補充であり、複数回補充・施設まとめ・倉庫制約を踏まえた最適化は未実装です。

タオルの約10%減は別の未承認提案です。使用数・既存予定を減らしません。次回納品までの安全余裕がある追加案だけから減量します。**追加案と減量提案は既存の倉庫搬出・上段の発注計算には含めません**。これらを実行計画へ採用する操作は、予定／実績の所有権管理とあわせて次の段階で整備します。

## 計画の範囲・留意点

- 当日・翌日・翌々日の3日を表示し、倉庫予測はその期間の納品に必要な次回納品まで延長します。現行の承認済み期限は2026/10/31です。期限外は「未作成」と表示し、空欄や0の計画を捏造しません。
- 既存Excel記載の入庫・使用・納品を前提とした予測です。空欄の朝在庫や計算結果が未取得の数式は未確認です。通常の入出庫欄の空欄は「記載なし」として予測し、実施・実在庫を保証しません。
- 業者納品前の搬出で一時的に足りないケースは、日末が正でも別に表示します。納品→搬出→入庫→使用の順序・時刻が確認された場合だけ該当チェックを選びます。日付・ファイルを変えるとこの確認をリセットします。
- 倉庫出庫は熊本・出水の部屋入庫から独立集計し、八代を含めません。八代の業者条件は未確定のため熊本の発注単位・曜日を適用せず、直接搬入・未配分を別表示します。
- PLの今回だけの件数差除外は、このリネン計画の入出庫計算には影響しません。元データの修正は行いません。
